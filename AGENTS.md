# Reglas de desarrollo

- Todos los comentarios de código y las docstrings deben escribirse en español.
- Mantener identificadores, nombres internos y protocolos en inglés.
- Conservar los textos legales originales y las atribuciones de terceros.
- Separar Core, servicios, módulos y frontend QML; cargar motores pesados al usarlos.
- Preservar funcionalidades y archivos del usuario. Usar pruebas con datos sintéticos.
- Leer DESIGN.md antes de cambios visuales y ejecutar las verificaciones que
  correspondan. No afirmar compatibilidad de un sistema sin pruebas en ese sistema.
- Mantener credenciales, perfiles, datos de campo, SDK y modelos grandes fuera de Git.
